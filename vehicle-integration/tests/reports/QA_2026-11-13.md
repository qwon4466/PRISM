## 3. 발견 사항

0. **(수정함, 심각) 자동차 라이브러리가 없는 기기에서 앱 시작 시 crash.** 휴대폰 AVD에서 `PrismViewModel` 생성 중 `NoClassDefFoundError: android.car.hardware.property.CarPropertyManager$CarPropertyEventCallback` 이 발생했다. 기어 콜백 필드가 생성자에서 바로 만들어져 `android.car` 를 불러왔고(`uses-library required=false` 라 휴대폰에는 없음), 연결 코드의 `runCatching` 보호 밖이었다. 콜백을 `by lazy` 로 바꿔 AAOS 연결이 성공할 때만 만들도록 했다. 수정 후 휴대폰 UI 테스트 7/7 PASS. 기어 기능 자체는 바뀌지 않았다(같은 인스턴스로 등록·해제). Pleos 에뮬레이터 재확인은 하지 않았다.
1. **(조치함) `index.json` 이 쓰는 도구에 따라 달라짐.** 파이프라인(Kotlin)과 Mock 생성기(Python)가 Mock 순서·JSON 공백을 다르게 써서, 마지막에 돌린 도구에 따라 시나리오 목록 순서가 바뀌었다. Mock 생성기를 파이프라인과 같은 규칙(이름순, 공백 없음)으로 맞추고 두 결과가 바이트 단위로 같음을 확인했다.
2. **(04 담당 확인 필요) 04 테스트 하나가 조용히 건너뛰어짐.** `TeamContractCompatibilityTest.dropoutScenario_unknownIsNeverShownAsWarning` 은 `vehicle-integration/.../scenarios/dropout` 을 찾는데, 05 가 통합하며 Mock 이름을 `mock_dropout` 으로 바꿔 `assumeTrue` 로 SKIP 된다(실패로 안 보임). "판단 불가 차량을 빨간 경고로 그리지 않는다" 검사가 현재 돌지 않는다. 04 테스트 경로를 `mock_dropout` 으로 바꾸거나, 실제 03 `sensor_dropout` 을 쓰도록 04 담당자 확인 필요(05 는 04 파일을 고치지 않음). 같은 동작은 이번 수동 QA(2절 데이터 누락 행)에서 확인했다.
3. **(미연결) 02 위험 엔진.** PR #8 로 05 형식 RiskFrame 을 내는 `engine02-kotlin` 이 들어왔지만 아직 파이프라인에 연결하지 않았다(사용자 결정으로 보류). 실제 엔진 시나리오에는 위험 등급이 없다.
4. **(환경) Pleos 에뮬레이터 앱 띄우기.** `am start` 로 띄운 앱이 내비 화면 뒤에 가려지고, 하단 앱바 아이콘이 열기/숨기기 토글이라 상태를 로그(`GnbAppButton`)로 확인하며 눌러야 한다. 이전 실행에서는 에뮬레이터 Pleos HAL 서비스 재시작과 `/sdcard` 손상이 있었다(앱과 무관).
5. **(확인 필요) 리플레이 슬라이더 탭 이동.** adb 탭으로는 슬라이더 위치가 바뀌지 않았고 드래그로만 이동했다. 실제 손가락 탭에서도 그런지 실기기 확인 필요.
6. **(기존) 위치 권한 동의 창.** `FUSED_LOCATION` 런타임 동의 창이 차량 홈에서 앞에 보이지 않아 `pm grant` 로 허용했다(SDK_COMPATIBILITY.md).
