# PRISM 통합 APK 0.3.0 개발 브랜치 변경 사항

이 APK는 Pleos AVD에서 합성 교통 시나리오를 재생하는 개발용 Debug 빌드다. 실제 주변 차량 감지·실도로 위험 판단이나 02 엔진의 검증된 출력이 아니다.

## 0.2.0과 달라진 점

| 항목 | 0.2.0 | 0.3.0 |
| --- | --- | --- |
| 화면 | 항상 어두운 화면 | 밝은 테마, 한국어 상황 이름과 예시 데이터 표시 |
| 위험 표시 | 실제 7개 시나리오에는 위험 프레임이 없어 빈 상태, Mock의 미래 위험 다각형이 현재 차 주변 박스처럼 보일 수 있음 | 13개 시나리오의 현재 VehicleFrame에서 자차 기준 간격·접근 속도·끼어들기·급감속을 계산한 **시뮬레이션용 추정** 표시 |
| 차량 표시 | 위험 영역과 차량 그림의 위치 관계가 혼동됨 | 각 차량 몸체와 상태 박스에 동일한 자차 상대 좌표 변환을 적용하고, 차량별 보통·주의·위험·판단 보류와 추정 간격(m)을 표시 |
| 알림 | Pleos Context Mode에서 WARNING 전환 순간 한 번 TTS | 앱이 전면에서 재생 중일 때 위험이 유지되면 약 4.5초 간격으로 합성 경고를 반복, 두 음 알림음 추가, 켜기/끄기 제공. Pleos TTS를 우선 사용하고 Android TTS로 대체 |
| 메모리 | 목록으로 복귀해도 이전 타임라인 유지 | 새 상황 선택·목록 복귀 때 이전 타임라인과 계산 결과 해제 |

위험 추정은 현재 차량 간 간격과 상대 속도를 사용하는 표시용 휴리스틱이다. 같은 경로의 앞·뒤 차량과 자차 차선으로 접근하는 차량을 구분하고, 관측이 불확실하거나 프레임이 오래된 경우 판단을 보류한다. **차량 제어, ADAS 센서 입력, 02 RiskFrame 엔진 통합은 포함되지 않는다.**

## 재현·테스트

- 빌드: JDK 17에서 `.\gradlew.bat :replay:test :adapters:test :app:testDebugUnitTest :app:assembleDebug`
- 시나리오 검사: 13개 assets 전체의 차량 ID·시각 대응, 정상 주행의 오경고, 앞차 거리 감소에 따른 보통→주의→위험, 끼어들기·급정거·뒤차 접근 원인, 박스 중심 좌표를 단위 테스트로 검증.
- Pleos AVD: `Pleos_Connect_v2.1.0` Android 14 사용자 10에서 APK 설치와 라이트 선택 화면을 확인했다. UI 계측 검사에서 13개 시나리오 모두 로드되고 차량별 평가가 생성됨을 확인했다. 박스와 차량 중심의 좌표 일치는 단위 검사로 확인했다. 에뮬레이터의 시스템 서비스 재시작으로 위험 구간의 시각 캡처는 아직 완료하지 못했다.
- 음성: AVD 로그에서 Pleos TTS 초기화(`pleosSpeechReady=true`)와 알림음 로딩(`chimeReady=true`)을 확인했다. 반복 발화와 실제 스피커 청취 품질은 추가 확인이 필요하다.

## 에뮬레이터 재검증 중 발생한 문제

- 2 GB 메모리로 부팅한 AVD의 `system_server`가 재시작했고 Pleos 지도·드라이빙뷰 프로세스에 `DeadSystemException`이 기록됐다. 그때 Windows 가용 물리 메모리는 약 0.44 GB였다. 호스트 메모리 압박이 유력하지만 `system_server`의 최초 종료 원인은 로그로 확정하지 못했다. PRISM 프로세스의 `FATAL EXCEPTION`은 확보한 로그에 없었다.
- Pleos 런처는 앱을 TaskView에 넣는다. `adb am start` 직후 앱 태스크가 `visible=false`인 동안 드라이빙뷰가 전면에 있었고, 이때 화면 캡처가 앱 대신 런처를 담았다. 앱 화면을 보려면 런처의 PRISM 아이콘으로 TaskView를 전면에 둬야 한다.
- 한 번의 계측 재검사는 이전 테스트 APK가 변경 전 `openScenario(String)`을 호출해 `NoSuchMethodError`가 났다. 같은 소스에서 테스트 APK를 다시 빌드해 성공했지만, 사용자의 요청에 따라 에뮬레이터 재실행은 중단했다. 따라서 이 버전의 최종 APK에 대한 13개 시나리오 계측 재검사 완료를 주장하지 않는다.

APK: `dist/PRISM-vehicle-v0.3.0-debug.apk` (Debug 서명, 테스트용). 설치 시 기존 `com.prism.vehicle.app` 0.2.0 위에 업데이트된다. 소스 변경은 `vehicle-integration/` 안에만 적용했다.

## 개발 언어 정리 (2026-11-13)

- 앱 실행 코드는 Kotlin을 유지했다. Python 보조 도구 3개는 Java 알림음 생성기와 Kotlin Mock 생성·예측 평가 도구로 교체했다. Gradle 설정은 Kotlin DSL이다.
- Java 생성 알림음은 기존 WAV와 SHA-256이 같다. Kotlin Mock 생성 결과는 기존 6개 시나리오 JSONL 1,713행에서 숫자 표기(`25`/`25.0`)를 제외하고 일치한다. 예측 평가와 Mock 생성 Gradle 작업을 실행했다.
- APK는 변경된 Mock provenance 경로를 반영해 다시 빌드했다. 관련 단위 테스트 46개가 통과했다. 이번 언어 변경 뒤 에뮬레이터 재검사는 수행하지 않았다.
