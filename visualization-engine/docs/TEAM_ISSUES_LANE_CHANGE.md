# 팀 이슈: 차선 변경·예측 경로가 비현실적으로 보이는 문제 (2026-11-13)

04 시각화 엔진에서 원인을 추적한 결과입니다. 04 쪽 표시 문제는 `fix/road-flow-direction` 브랜치에서 수정했습니다. 아래 항목은 각 담당 폴더에서 수정이 필요하며, 04는 이 폴더들을 수정하지 않았습니다.

## 04에서 수정한 것 (참고)

| 문제 | 수정 |
|---|---|
| 도로 차선이 고정되어 있어, 25 m/s로 달리는 자차가 정지한 것처럼 보이고 자차보다 느린 차량이 후진하는 것처럼 보임 | 차선 점선과 셰브런을 자차 주행거리만큼 흘려 보냄 (`RoadOdometer`, `drawRoad(roadOffsetM)`) |
| 예측 경로를 자차 상대 운동(`RELATIVE_TO_EGO`)으로 그려, 자차보다 느린 차량의 경로가 뒤나 옆으로 누움. 차선 변경 차량은 경로가 거의 수평이 되어 "여러 차선을 가로질러 파고드는" 것처럼 보임 | 기본값을 `AS_GIVEN`(도로 기준)으로 변경. MOCK 6종에서 진행 방향과 30° 이상 어긋난 경로가 1,418개에서 0개로 줄었음. 충돌 영역 판정은 평행 이동에 영향을 받지 않아 결과가 같음 |

## 05 (vehicle-integration) — MOCK 데이터

1. **`lane_change` MOCK의 차선 변경이 직선 대각 이동이다.**
   - 위치: `app/src/main/assets/scenarios/lane_change/vehicle_frames.jsonl` (생성 스크립트 `tests/tools/make_mock_scenarios.py`)
   - 현상:
     - car_02가 3.0~5.5초 동안 vx = −1.44 m/s로 일정하게 움직인다.
     - heading이 1.571 → 1.633 → 1.571로 순간 전환된다.
     - 곡선 궤적, 차선 중앙 정렬, 안전 공간 확인이 없다. 자차보다 느린 상태(23 대 25 m/s)에서 약 12 m 앞으로 끼어든다.
   - 제안: 03 `sim_lane_change`처럼 heading이 서서히 돌았다가 수렴하는 궤적(예: 5차 다항식 또는 자전거 모델)으로 다시 생성한다.
2. **MOCK 예측 경로가 목표 차선을 지나쳐 계속 진행한다.**
   - 위치: `lane_change/prediction_frames.jsonl`
   - 현상:
     - 3.5초 시점 car_02 예측이 x = 1.3 → −0.1 → −1.6 m이다. 4.5초 시점에는 −3.0 m까지 간다(왼쪽 차선).
     - 실제 차량은 x = 0에서 멈춘다.
     - mode는 `lane_keep`이다.
   - 제안: 차선 변경 중인 차량은 목표 차선 중앙에서 가로 이동을 멈추는 예측을 쓰고, mode를 `lane_change`로 표기한다.

## 01 (prediction-engine)

3. **등속 외삽(CV)이 가로 속도를 그대로 연장한다.**
   - 위치: `src/main/kotlin/com/prism/prediction/Baseline.kt` (`current.x + vx * seconds`)
   - 현상: `sim_lane_change` car_08은 5.6초 시점 vx가 4.6 m/s이므로, 5초 예측이 가로로 약 23 m(약 6차선)까지 뻗는다.
   - 제안: 차선 폭(`laneWidthM`)을 기준으로 목표 차선 중앙에서 가로 변위를 제한한다. 또는 차선 변경 모드에서 `laneChangeDurationS` 이후 vx를 0으로 수렴시킨다.

## 03 (simulation-engine)

4. **차선 변경 취소 시나리오가 없다.** 요청된 검증 시나리오 중 E(공간 부족으로 진입 취소)에 해당하는 시나리오가 없다. MOBIL 안전 조건으로 취소되는 경우를 강제 이벤트로 재현하는 시나리오 추가를 제안한다.
5. **자차가 정지하는 시나리오가 없다.** 13종 모두 자차 최소 속도가 5.2 m/s 이상이다. 검증 항목 A~C(자차 정지)와 "정차 후 재출발"에 해당하는 시나리오 추가를 제안한다.

## 공통 계약 (팀장 승인 필요)
